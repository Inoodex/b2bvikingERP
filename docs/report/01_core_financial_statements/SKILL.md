# 🏛️ Core Financial Statements — Architecture & PDF Standards (SKILL.md)

This skill document defines the architectural standards, performance guidelines, security practices, and implementation templates for **Core Financial Statements** in B2B Viking ERP.

---

## 📌 1. Architectural Principles

### 1.1 The Ephemeral Dynamic Storage Model (Zero Stale Data, Zero Disk Bloat)
Financial reports deal with active fiscal ledgers where journals, invoices, and payment adjustments occur continuously. Serving cached or previously generated static files is strictly prohibited.

```
[Client Request: Export PDF with Filters]
                 │
                 ▼
[1. Controller: Immediate Dispatch] ── Dispatches GenerateFinancialReportPdfJob (< 50ms)
                 │                    Frees PHP-FPM web worker immediately!
                 ▼
[2. Background Queue Worker] ── Fetches up-to-the-second live database records.
                 │             Purges prior temporary files for this user/report.
                 ▼
[3. Generate Ephemeral PDF] ── Writes to `storage/app/temp_reports/{unique_name}.pdf`.
                 │
                 ▼
[4. Bell Icon Notification] ── Dispatches download notification to navbar bell icon.
                 │
                 ▼
[5. Safe Static Download] ── Streams static file from disk (0% CPU, 0MB RAM load).
                 │
                 ▼
[Result: 100% Live Data, Zero Server 503 Crashes, Seamless User Experience]
```

### 1.2 Dedicated Background Queue Processing
- Every single financial PDF generation is dispatched asynchronously to `App\Jobs\GenerateFinancialReportPdfJob` (implementing `ShouldQueue`).
- The controller never renders DomPDF synchronously, guaranteeing that PHP-FPM web workers are never starved or frozen.
- The user receives an instant Toastr notification: *"Report generation started in the background. Check notifications when ready."*
- When the Queue Worker finishes rendering, it registers an alert in the top navbar bell icon with a direct download link.

### 1.3 Total Ban on `window.print()`
Browser `window.print()` is completely banned for all financial statements.
- **Why banned:**
  - Injects browser headers/footers (file URL, internal timestamps, page numbers).
  - Triggers ugly page breaks splitting ledger rows and statement summary cards.
  - CSS gradients and box-shadows print as muddy, illegible blocks.
  - Prints sidebar, navbar, and action buttons unless masked by complex CSS hacks.
- **Mandatory Standard:** Every statement must provide a dedicated, server-rendered **A4 Corporate Print PDF**.

## 🎨 2. A4 Corporate PDF Visual & Layout Standards

All financial statements must render clean, audit-ready A4 documents matching international accounting (IFRS/GAAP) presentation:

### 2.1 Page Setup & Typography
- **Paper Size:** A4 Portrait (`setPaper('a4', 'portrait')`) or A4 Landscape (`setPaper('a4', 'landscape')` for General Ledger).
- **Font Stack:** Clean Sans-Serif (`DejaVu Sans`, `Helvetica`, or system sans-serif) for full UTF-8 and currency symbol (`kr.`) compatibility.
- **Base Font Size:** `9pt` to `10pt` for body rows, `8pt` for metadata/footers, `12pt` to `16pt` for document headers.

### 2.2 Corporate Document Header
Every financial PDF must start with a standardized corporate header without any dummy/fake placeholders:
```html
<div class="company-header">
    <table width="100%">
        <tr>
            <td width="60%">
                <h2 class="company-name">{{ $company->name ?? $settings->site_name ?? 'Copenhagen Tourist Point' }}</h2>
                <p class="company-details">
                    @if(!empty($company->vat_number)) CVR / VAT No: {{ $company->vat_number }}<br>@endif
                    Address: {{ $company->address ?? $settings->address ?? 'Copenhagen, Denmark' }}<br>
                    Email: {{ $company->email ?? $settings->contact_email ?? 'finance@b2bviking.com' }}
                </p>
            </td>
            <td width="40%" class="text-right">
                <h3 class="statement-title">{{ $statementTitle }}</h3>
                <p class="statement-meta">
                    <strong>Period:</strong> {{ $dateRangeLabel }}<br>
                    <strong>Generated:</strong> {{ now()->format('d M Y, H:i:s') }}<br>
                    <strong>Generated By:</strong> {{ auth()->user()->name ?? 'System' }}
                </p>
            </td>
        </tr>
    </table>
</div>
```

### 2.3 Accounting Table Standards
- Alternating row background (`#fbfbfb` vs `#ffffff`).
- Numbers must always be **right-aligned** (`text-right`) and formatted with standard accounting notation (`number_format($val, 2)`).
- Debit balances in green or dark slate, Credit balances in primary blue or dark slate.
- Table headers with subtle `#e9ecef` background, clean `1px solid #dee2e6` borders.
- Zero usage of heavy dark fills (saves customer printer ink).
- Add CSS rule: `tr { page-break-inside: avoid; }` to prevent rows from breaking across page folds.

### 2.4 Audit & Sign-off Footer
Every financial PDF must include an official 3-column verification signature block at the end:
```html

    <tr>
        <td width="33%" class="text-center">
```

## 💻 3. Controller & Service Implementation Pattern

### 3.1 Ephemeral File Manager Helper Pattern
Use a dedicated private or helper method to encapsulate the ephemeral file lifecycle:

```php
declare(strict_types=1);

namespace App\Http\Controllers\Backend;

use App\Models\GeneralSetting;
use Barryvdh\DomPDF\Facade\Pdf;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\File;
use Symfony\Component\HttpFoundation\BinaryFileResponse;

class FinancialReportController extends Controller
{
    /**
     * Helper to render, save to ephemeral storage, purge old files, and return auto-deleting download.
     */
    private function streamEphemeralPdf(
        string $view,
        array $data,
        string $filePrefix,
        string $paper = 'a4',
        string $orientation = 'portrait'
    ): BinaryFileResponse {
        $userId = auth()->id() ?? 0;
        $tempDir = storage_path('app/temp_reports');

        if (!File::exists($tempDir)) {
            File::makeDirectory($tempDir, 0755, true);
        }

        // 1. Purge any previous temporary files for this user & prefix
        $pattern = $tempDir . "/{$filePrefix}_u{$userId}_*.pdf";
        foreach (glob($pattern) as $oldFile) {
            @unlink($oldFile);
        }

        // 2. Generate new PDF with live data
        $timestamp = now()->format('Ymd_His');
        $fileName = "{$filePrefix}_{$timestamp}.pdf";
        $filePath = "{$tempDir}/{$filePrefix}_u{$userId}_{$timestamp}.pdf";

        $pdf = Pdf::loadView($view, $data)->setPaper($paper, $orientation);
        $pdf->save($filePath);

        // 3. Stream download and automatically delete file upon completion
        return response()->download($filePath, $fileName, [
            'Content-Type' => 'application/pdf',
            'Cache-Control' => 'no-store, no-cache, must-revalidate',
        ])->deleteFileAfterSend(true);
    }
}
```

## 🚫 4. Financial PDF Anti-Patterns to Avoid

| # | Anti-Pattern | Why It Is Harmful | Correct Enterprise Alternative |
|:--|:---|:---|:---|
| 1 | **Using `window.print()` in Blade** | Prints messy HTML, sidebars, cut-off tables, dark gradients, browser URLs. | Use dedicated DomPDF Blade template styled for A4. |
| 2 | **Permanent File Storage** | Storing report PDFs indefinitely serves stale data when ledgers change. | Ephemeral storage + live DB query on every export + `deleteFileAfterSend(true)`. |
| 3 | **Direct `->download()` without file buffering** | High memory spike in PHP RAM during transmission, risk of 503 crash. | Buffer to ephemeral file on disk, then stream via `response()->download()`. |
| 4 | **Paginating Trial Balance / P&L** | A balance sheet or P&L broken into pages 1, 2, 3 in DataTables violates accounting integrity. | Render full hierarchical statement via single aggregate query. |
| 5 | **N+1 Queries in Balance Calculation** | Looping through 200 COA accounts and running `whereHas('journalEntry')` 200 times. | Use single aggregate query (`buildAggregate`) grouped by `account_id`. |
| 6 | **Hardcoded Currency Symbols** | Breaks multi-currency enterprise support. | Dynamic currency from `GeneralSetting::first()->currency_icon ?? 'kr.'`. |
| 7 | **Missing Date Range in PDF Header** | Auditor cannot verify what period the statement covers. | Always render explicit `date_from`, `date_to`, or `as_of_date` in the PDF header. |

## ✅ 5. Definition of Done (DoD) for Financial PDF Exports
A Core Financial Statement export is only considered enterprise-ready when:
1. `declare(strict_types=1);` is enforced in the controller and helper classes.
2. The export generates fresh, live data every time (0% stale data).
3. Old temporary files for that user are purged before generating new ones.
4. Downloaded files are automatically deleted from server storage via `deleteFileAfterSend(true)`.
5. Active UI filter values (`date_from`, `date_to`, `account_id`, `as_of_date`) are strictly preserved in the generated PDF.
6. The PDF includes company details, generation timestamp, logged-in user name, and signature sign-off lines.
7. Automated feature test asserts:
   - Route returns HTTP 200 with `Content-Type: application/pdf`.
   - File download contains expected header metadata and balanced amounts.
